# scholarship

奖学金评审的进程内排名库（Go）。管理员在评审持续打分时预览获奖名单，
每份预览的评分、权重与完整评审人数都来自同一时刻的完整状态。

## 设计

- `Board` 使用一把 `sync.RWMutex`：`PutScores` / `SetWeights` 持写锁，
  `PreviewAwards` 持读锁并在锁内完成全部计算，因此所有操作可线性化，
  预览天然对应调用区间内某一时刻的完整状态，补丁不会部分可见。
- 分数使用 `math/big.Rat` 精确有理数：先对每名填齐全部评分项的评审
  求加权平均，再等权平均；无完整评审的申请不参与排名。
- 排名按分数降序，同分按申请 ID 字典序，截取前 K 名。

## API

```go
b := scholarship.New(
    map[string][]string{"app-1": {"r1", "r2"}}, // 申请 -> 已分配评审
    []string{"a", "b", "c"},                    // 1..5 个评分项
    map[string]int{"a": 1, "b": 2, "c": 3},     // 权重，每项 1..100
    2,                                          // 名额 K
)
b.PutScores("app-1", "r1", map[string]int{"a": 10, "b": 9}) // 原子补丁，每项 1..10
b.SetWeights(map[string]int{"a": 3, "b": 2, "c": 1})        // 原子替换整组权重
awards := b.PreviewAwards()                                 // 最多 K 名候选人
```

非法输入（未知申请/评审/评分项、分值或权重越界、权重未覆盖全部评分项）会 panic。

## 运行测试

```sh
go test ./...        # 全部测试
go test -race ./...  # 含竞态检测
```

测试覆盖：串行参考计算对拍（残缺评审补齐、重复提交、四舍五入相同但
精确分数不同并决定最后一个名额），以及并发交错提交补丁 / 替换权重 /
执行预览时，每份预览都对应其调用区间内某个已提交的完整状态。
